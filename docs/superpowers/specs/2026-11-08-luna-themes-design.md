# Темы оформления Luna: «Лунный свет», «Дневная луна» и выбор при первом запуске

Дата: 2026-11-08 · Ветка: `feat/themes`

## Зачем

Текущая палитра (`PALETTE` в `luna/ui/theme.py`: `moon`, `peri`, `blue`, `mauve`…) названа по
оттенкам, а не по ролям. Поэтому один и тот же цвет значит разное в разных местах (`mauve` —
то ошибка, то предупреждение, то режим плана), REPL местами использует стандартные `bold red` /
`bold green` / `yellow`, а светлого варианта нет вообще. Около 25 файлов берут hex-цвета
напрямую.

Цель — сделать оформление цельным и выбираемым, как в Claude Code:

- две основные темы со страницы палитр: **Лунный свет** (тёмная) и **Дневная луна** (светлая);
- **Авто**: Luna определяет фон терминала и сама выбирает тёмную или светлую;
- варианты для дальтоников и варианты «только ANSI»;
- окно выбора темы с живым примером при первом запуске (всем, у кого тема не выбрана, включая
  существующих пользователей), в `luna setup` и по команде `/theme`;
- одна система токенов для REPL (`rich`) и TUI (`Textual`);
- блоки, выделенные фоном и полосой слева, вместо скруглённых рамок;
- один спиннер и один таймер анимаций;
- проверка контраста.

Критерий успеха: никакого hex-цвета вне файлов тем; все тексты встроенных тем ≥ 4.5:1 к фону,
панели и элементу; переключение темы в TUI видно сразу, без перезапуска; первый запуск
показывает выбор, повторный — нет.

## Токены

Тема — набор цветов по ролям. Имена (в TOML через `_`, в Textual-CSS через `-`):

| Токен | Роль |
|---|---|
| `bg` | фон экрана |
| `panel` | фон приподнятых блоков: сайдбар, статус-бар, свои сообщения, строки инструментов |
| `element` | фон блоков поверх панели: окно подтверждения, выделенная строка списка |
| `border` | рамка поля ввода, разделители |
| `border_subtle` | тихие разделители |
| `text` | основной текст |
| `muted` | второстепенный текст (время, пути, подсказки) |
| `strong` | заголовки, выделенный текст |
| `primary` | акцент Luna: курсор, своё сообщение, фокус, текущая сессия |
| `on_primary` | текст на `primary` |
| `accent` | второй акцент: режим плана, вордмарк |
| `tool` | имя инструмента |
| `code` | inline-код |
| `ok` / `warn` / `err` | статусы |
| `add` / `del` | строки diff |
| `add_bg` / `del_bg` | фон строк diff |

Плюс метаданные: `name`, `title` (русское название), `dark` (bool), `ansi` (bool).

Цвет никогда не единственный носитель смысла (правило ui-ux-pro-max «Color Only», severity High):
статус инструмента дублируется значком (`✓` / `✗` / спиннер), строки diff — префиксом `+` / `-`.

## Набор тем

Файлы `luna/ui/themes/*.toml`, имя файла = идентификатор темы.

| Идентификатор | Название | Основа |
|---|---|---|
| `moonlight` | Лунный свет | значения со страницы палитр |
| `daymoon` | Дневная луна | значения со страницы палитр |
| `moonlight-cb` | Лунный свет · для дальтоников | `moonlight`, но ok/add синие, err/del оранжевые |
| `daymoon-cb` | Дневная луна · для дальтоников | то же для светлой |
| `ansi-dark` | Тёмная · цвета терминала | 16 цветов ANSI, `ansi = true` |
| `ansi-light` | Светлая · цвета терминала | то же для светлого фона |

`auto` — не файл, а правило: `moonlight` или `daymoon` по фону терминала.

Значения `moonlight` и `daymoon` — ровно те, что на странице палитр
(https://claude.ai/artifact/NTBNMoeSM3YDfFKgDXxp3Z), с исправленным контрастом светлой.

Варианты для дальтоников (палитра в духе Okabe–Ito, проверено расчётом):

| Токен | `moonlight-cb` | `daymoon-cb` |
|---|---|---|
| `ok`, `add` | `#6cb8ee` (8.75 к bg) | `#0a62a3` (5.96) |
| `err`, `del` | `#f08a4b` (7.6) | `#9a4806` (≥ 4.5 к element) |
| `warn` | `#e8d36a` (12.6) | `#6f5c00` (6.1) |
| `add_bg` | `#142536` | `#dbe9f6` |
| `del_bg` | `#33200f` | `#f8e3d2` |

ANSI-темы пишут цвета именами (`ansi_blue`, `ansi_bright_black`, `default`…): в Textual они
идут как есть при `Theme(ansi=True)`, в `rich` переводятся в `blue`, `bright_black`, `default`.
Фон и панели в ANSI-темах — `default`: блоки различаются только полосой слева. Проверка
контраста к ANSI-темам не применяется (реальные цвета знает только терминал).

### Свои темы

`~/.config/luna/themes/<id>.toml`, тот же формат; ключ `extends = "moonlight"` берёт
недостающие токены из встроенной темы. Своя тема с тем же идентификатором, что у встроенной,
не перекрывает встроенную (предупреждение, файл пропускается). Битый файл или неизвестный
токен → предупреждение и тема пропускается, Luna работает дальше.

## Модуль тем

`luna/ui/themes/__init__.py` — единственное место, где цвета превращаются в стили:

```python
@dataclass(frozen=True)
class ThemeSpec:
    id: str
    title: str
    dark: bool
    ansi: bool
    tokens: Mapping[str, str]

def available_themes() -> list[ThemeSpec]          # встроенные + пользовательские
def load_theme(theme_id: str) -> ThemeSpec        # KeyError → вызывающий берёт auto
def resolve(choice: str, *, dark_terminal: bool) -> ThemeSpec   # "auto" → moonlight/daymoon
def rich_theme(spec: ThemeSpec) -> rich.theme.Theme
def textual_theme(spec: ThemeSpec) -> textual.theme.Theme
def contrast_issues(spec: ThemeSpec) -> list[str]
def active() -> ThemeSpec                          # тема текущего процесса
def set_active(spec: ThemeSpec) -> None
```

- `rich_theme` даёт стили `luna.<токен>` (`luna.primary`, `luna.muted`, `luna.ok`…) плюс
  смысловые стили, на которые уже опирается код (`luna.title`, `luna.prompt`, `luna.tool.name`,
  `luna.warn`, `luna.error`, `luna.ok`…), но собранные из токенов.
- `textual_theme` заполняет стандартные поля Textual (`primary`, `background`, `surface`,
  `panel`, `success`, `warning`, `error`, `foreground`, `dark`, `ansi`) и кладёт все токены в
  `variables`, так что в `luna.tcss` доступны `$bg`, `$panel`, `$element`, `$text`, `$muted`,
  `$primary`, `$ok`… Старые имена (`$moon`, `$peri`, `$moon-dim`, `$mauve`) удаляются: CSS
  переписывается на новые.
- Пользовательская тема со слабым контрастом: `contrast_issues` даёт предупреждение
  (показывается один раз при запуске), а цвет текста подтягивается по светлоте до 4.5:1.

`PALETTE` и `TUI_VARIABLES` удаляются. Всё, что сейчас берёт `PALETTE[...]` или
`TUI_VARIABLES[...]`, переходит на стили `luna.*` (rich) или CSS-классы/переменные (Textual).
Градиенты (вордмарк, баннер) считают цвета из `active().tokens`.

## Определение фона терминала

`luna/ui/termbg.py`, вызывается один раз в процессе, до старта Textual / REPL:

1. `LUNA_THEME` в окружении — если задан, используется как выбор темы целиком (для CI и
   скриптов); определение фона не нужно, если это не `auto`.
2. Запрос OSC 11 (`\x1b]11;?\x07`) в `/dev/tty`, режим raw, ожидание ответа до 100 мс; ответ
   `rgb:RRRR/GGGG/BBBB` → относительная яркость < 0.5 → тёмный.
3. Иначе `COLORFGBG` (`"15;0"` → фон 0 → тёмный; фон 7 или 15 → светлый).
4. Иначе тёмный.

Без TTY (pipe, `luna run`, тесты) шаг 2 не выполняется. Разбор ответа OSC и `COLORFGBG` —
чистые функции, тестируются без терминала.

## Настройка

- `config.toml`: `[ui] theme = "auto"` (ключ `ui.theme`, строка, добавляется в `KNOWN`);
  `luna config set ui.theme daymoon` работает как с остальными ключами.
- Неизвестное значение → предупреждение, используется `auto`.
- Выбор пишется в пользовательский конфиг (не в `.luna.toml` проекта).

## Выбор темы

### Первый запуск

Если в пользовательском конфиге нет `ui.theme` и Luna запущена интерактивно (TTY, без
аргумента-промпта, не `luna run`), перед заставкой показывается выбор. Это касается и
существующих пользователей — один раз.

Экран (inline, не во весь экран, в духе Claude Code):

```
Выберите тему оформления
Сменить потом: /theme или luna config set ui.theme …

 › Авто (по фону терминала) — сейчас: Лунный свет
   Лунный свет
   Дневная луна
   Лунный свет · для дальтоников
   Дневная луна · для дальтоников
   Тёмная · цвета терминала
   Светлая · цвета терминала

 ┃ › добавь проверку пустого ввода            ← своё сообщение
 ┃ ✓ edit_file  luna/cli.py                   ← инструмент
   12   def parse(raw):
   13 - │   return raw.split()
   13 + │   if not raw: return []
   14 + │   return raw.split()
   Готово: пустой ввод больше не падает.      ← ответ, `code`-токен

 ↑↓ выбрать · Enter сохранить · Esc — Авто
```

- Пример перерисовывается при каждом движении курсора в выбранной теме (фон примера — `bg`
  темы, так что светлая тема видна и в тёмном терминале).
- Enter сохраняет выбор; Esc сохраняет «Авто» и пишет «тема: Авто · сменить — /theme»;
  Ctrl+C выходит из Luna, как в остальных подсказках, ничего не сохраняя.
- Реализация: `prompt_toolkit` (уже зависимость через `questionary`) `Application`
  с `full_screen=False`; пример рендерится через `rich` в ANSI-строку и вставляется как
  `ANSI(...)`. Модуль `luna/ui/theme_picker.py`, функция
  `pick_theme(console, *, current: str, dark_terminal: bool) -> str | None`.
- Без TTY выбор не показывается, тема — `auto`, в конфиг ничего не пишется.

### `luna setup`

Мастер получает шаг «Тема» (тот же `pick_theme`) перед выбором провайдера.

### `/theme`

Общая команда в `luna/commands/builtin.py`:

- `/theme` без аргумента → эффект `{"pick_theme": {"current": ..., "options": [(id, title)…]}}`;
- `/theme <id|auto>` → сохраняет в пользовательский конфиг, эффект `{"theme": id}`;
  неизвестная тема → ошибка-уведомление со списком допустимых.

TUI: эффект `pick_theme` открывает `ThemeModal` (наследник `ChoiceModal` с колбэком на
подсвеченный пункт). Подсветка пункта сразу применяет тему (`app.theme = …`); Enter
отправляет `/theme <id>`; Esc возвращает прежнюю тему. Эффект `theme` применяет тему через
`resolve` с фоном терминала, определённым при запуске.

REPL: `/theme` без аргумента вызывает `pick_theme`, затем `/theme <id>`; применение —
замена темы консоли `rich` (`set_active` + новый `Console`-тема через `push_theme`).

## Структура блоков (TUI)

Рамки остаются только у поля ввода (`round $border`, в фокусе `$primary`, в режиме плана
`$accent`). Остальное — фон и полоса слева (`border-left: outer` / `heavy` — символ `┃`,
выбирается тот, что лучше смотрится в pty; решение фиксируется в плане):

| Блок | Фон | Полоса слева |
|---|---|---|
| Своё сообщение | `$panel` | `$primary` |
| Строка инструмента | `$panel` | идёт `$muted` · готово `$ok` · ошибка `$err` |
| Окно подтверждения | `$element` | `$warn` |
| Выбор / ключ / да-нет | `$panel` | `$primary` |
| Уведомления warn / error | нет | `$warn` / `$err` |
| Текущая сессия в сайдбаре | `$element` | `$primary` (вместо заливки `$peri`) |

Ответ Luna — без фона и полосы, чистый текст на `$bg`: он главный.

REPL (`rich`) повторяет ту же логику там, где у него рамки: окно подтверждения
(`ui/approve.py`) — `Panel` без рамки, с полосой `┃` в `luna.warn`; заголовок хода
(`ui/turn.py`) — строка в `luna.muted`.

Diff везде (подтверждение в TUI и REPL, `/diff`): строки `+` — `add` на `add_bg`, `-` — `del`
на `del_bg`, контекст — `muted`.

## Анимация

`luna/ui/motion.py` — чистые функции без состояния:

```python
SPINNER = "⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏"
FRAME_SECONDS = 0.08
def spinner_frame(elapsed: float) -> str
def shimmer(text: str, elapsed: float, base: str, highlight: str) -> rich.text.Text
def motion_enabled() -> bool   # False при TEXTUAL_ANIMATIONS=none, NO_MOTION, ui.motion=false
```

- Брайлевский спиннер — у выполняющегося инструмента и у «Luna думает».
- Подпись «Luna думает» мерцает: светлое пятно `highlight` пробегает по `base` (как в OpenClaw).
- TUI: один `set_interval(FRAME_SECONDS)` в `LunaApp`, который обновляет зарегистрированные
  анимированные виджеты; `PulseGlyph` перестаёт заводить свой `auto_refresh`. Нет живых
  анимаций — таймер на паузе.
- REPL: `ui/progress.py` использует те же функции в своём `Live`.
- Без анимации: статичный `•` вместо спиннера, подпись без мерцания, счётчик секунд остаётся.
- Ключ `[ui] motion = true|false` (по умолчанию `true`), добавляется в `KNOWN`.

## Ошибки

- Нет файла темы / битый файл → предупреждение, `auto`.
- OSC 11 не ответил → `COLORFGBG` → тёмный; без сообщений.
- Запись конфига не удалась (права) → уведомление-ошибка; тема применяется на сессию.
- Выбор при первом запуске прерван Ctrl+C → выход без записи; следующий запуск спросит снова.

## Тесты

- Контраст: для каждой встроенной не-ANSI темы `text`, `muted`, `strong`, `primary`, `tool`,
  `code`, `ok`, `warn`, `err`, `add`, `del` ≥ 4.5:1 к `bg`, `panel`, `element`; `text` ≥ 4.5:1 к
  `add_bg`, `del_bg`; `on_primary` ≥ 4.5:1 к `primary`.
- Полнота: каждая встроенная тема задаёт все токены.
- Загрузчик: `extends`, неизвестный токен, битый TOML, конфликт идентификатора.
- `resolve("auto", dark_terminal=…)`, неизвестное значение.
- `termbg`: разбор `rgb:ffff/ffff/ffff`, `rgb:00/00/00`, мусор; `COLORFGBG` варианты.
- Конфиг: `ui.theme`, `ui.motion` читаются и пишутся.
- Первый запуск: нет TTY → выбор не вызывается; ключ есть → не вызывается; нет ключа и TTY →
  вызывается (через подмену `pick_theme`).
- `/theme`: без аргумента → `pick_theme`; с аргументом → запись и эффект; неизвестная → ошибка.
- TUI (Pilot): смена темы меняет `$bg` у `ChatPane`; `ThemeModal` подсветка применяет, Esc
  возвращает; у строки инструмента класс статуса.
- `motion`: кадры спиннера, `motion_enabled` по окружению; в TUI один таймер.
- Сторож: в `luna/` (кроме `luna/ui/themes/`) нет литералов `#rrggbb` и стилей `red`/`green`/
  `yellow` (тест-grep).
- Живая проверка в pty 130×36 для каждой темы (скриншоты в scratchpad), затем critique + polish.

## Вне рамок

- Чтение всей ANSI-палитры терминала (OSC 4) и построение темы из неё — ANSI-темы уже дают
  «как в терминале» через родные цвета.
- Смена шрифтов, раскладки и текстов интерфейса.
- Отслеживание смены темы терминала во время работы (Auto решается при запуске).
