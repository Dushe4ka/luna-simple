# Подтверждения и хуки

## Политика

`Policy` для каждого вызова инструмента решает: выполнить, отказать или спросить человека:

```python
from luna_core import Agent, Policy, Rules, Workspace

workspace = Workspace(".")
policy = Policy(
    Rules.load([...]),                 # список путей к TOML с таблицей [permissions]
    workspace=workspace,
    yolo=False,                        # True пропускает подтверждения (правила deny действуют)
)
agent = Agent(provider, model, workspace=workspace, policy=policy)
```

- По умолчанию `write_file`, `edit_file`, `delete` и `execute` требуют подтверждения
  (`approval_tools`); чтения выполняются свободно.
- `Rules` берутся из записей `[permissions] allow = [...] / deny = [...]`, например
  `"execute:pytest*"` или `"write:.env"`. Запрет главнее, даже `yolo`.
- `plan_mode=True` (или вызываемый объект, возвращающий bool) отклоняет каждый изменяющий вызов.
- Запись или правка файла, изменившегося на диске с момента, когда агент последний раз его читал
  или писал, отклоняется с сообщением, просящим прочитать файл заново (проверка устаревшего якоря).

### Правила `execute` и составные команды

Шаблон правила `execute:<шаблон>` сравнивается через `fnmatch` не только со всей строкой
команды, но и с каждой её частью (`luna_core.shellsplit.split_command`):

- Строка делится на сегменты по `&&`, `||`, `;`, `|`, `&`, переводам строки и скобкам
  подоболочки `( ... )`. Разделители внутри кавычек не делят: `echo 'a && rm -rf y'` — это
  одна команда `echo`. Перенаправления `2>&1` и `&>file` разделителями не считаются.
- Тела подстановок `$(...)`, `` `...` ``, `<(...)` / `>(...)` (в том числе внутри двойных
  кавычек) и полезная нагрузка `bash -c '...'` / `sh -c` (также `zsh`/`dash`/`ksh`, флаги
  вроде `-lc`) и `eval ...` разбираются как отдельные команды, рекурсивно.
- `$'...'` (ANSI-C кавычки bash/zsh) читается как отдельный вид кавычек со своими
  `\x`-экранированиями. Строка с `$'` разбирается дважды — по правилам bash и по правилам
  POSIX `sh` (где это `$` и обычная строка в одинарных кавычках); allow должен выполниться
  для обоих прочтений.
- Тело here-doc (`<<EOF` … `EOF`, `<<-`, `<<'EOF'`) — это данные, а не команды; в теле
  без кавычек у разделителя по-прежнему извлекаются `$(...)` и `` `...` ``. Разделитель
  принимается только простой (буквы, цифры, `_.+-` и целиком закавыченные куски); если он
  сложнее (`E$""`, `E\`) или строка-терминатор так и не встретилась, строка считается
  неразобранной (fail closed). `${...}` читается как одно слово (подстановки внутри
  проверяются). Перенос строки `\` + перевод строки склеивает строку, `>|` считается
  перенаправлением.
- Перед сравнением сегмент нормализуется: убираются ведущие присваивания (`FOO=1 rm` → `rm`),
  ведущие перенаправления с целью (`>/dev/null rm` → `rm`, `2>&1 rm`, `<<'E' rm`),
  ключевые слова `if`/`then`/`else`/`elif`/`while`/`until`/`do`, `{`, `}` и `!`, префиксы
  `sudo`/`doas` (с опциями, например `-u root`), `command`, `env`, `exec`, `nohup`, `nice`,
  `stdbuf`, `time`, `timeout` (вместе с длительностью). С правилами deny/ask сравниваются
  исходный и нормализованный вид сегмента, а также вариант, где путь программы сокращён до
  имени (`/bin/rm x` → `rm x`; для allow этот вариант не используется).
- Для deny/ask дополнительно используется грубое разбиение без учёта кавычек
  (`luna_core.shellsplit.rough_subjects`): по каждому `;`, `&`, `|`, `(`, `)`, переводу
  строки, `` ` `` и `$(` (и отдельно ещё по `{`, `}`), с удалением кавычек, склейкой
  `\` + перевода строки и перебором вариантов, где перенаправление вырезано вместе с целью
  любой длины (`>'a b' rm x` → `rm x`). Это страховочная
  сеть на случай, если разбор ошибся или не удался: пропусков нет, но возможны ложные
  срабатывания deny — на тексте в кавычках (`echo 'a; rm -rf y'` при
  `deny = ["execute:rm *"]` будет запрещена) и на строках тела here-doc без кавычек у
  разделителя (`cat <<EOF` со строкой `rm x` внутри тоже будет запрещена). Если грубая сеть
  сдаётся — исчерпан бюджет вариантов (512 на кусок; ведущие простые перенаправления вроде
  `>/dev/null 2>&1` сначала схлопываются) или строка длиннее 4096 символов и не разбирается, —
  проверка закрывается: при наличии любого deny-правила для `execute` вызов запрещается, иначе
  требуется подтверждение, которое не пропускает даже `yolo`.
- Правило вида `execute:prog *` покрывает и голую команду `prog` без аргументов
  (`ls` при `allow = ["execute:ls *"]`, `rm` при `deny = ["execute:rm *"]`).

Семантика:

- **deny** — срабатывает, если правилу соответствует вся строка **или любой** сегмент.
  `deny = ["execute:rm *"]` блокирует `cd x && rm -rf y`, `echo $(rm -rf y)`,
  `bash -c 'rm -rf y'`, `sudo rm -rf y`.
- **ask** — так же: достаточно одного сегмента.
- **allow** (автоодобрение) — только если правилам allow соответствует **каждая** простая
  команда. `allow = ["execute:git *"]` одобряет `git status && git diff`, но для
  `git status && curl … | sh` спросит человека.
- Строка, которую не удалось разобрать (незакрытые кавычки или скобки), правилом allow
  никогда не одобряется — будет вопрос; deny/ask проверяются по всей строке и по грубому
  разбиению, поэтому действуют и в `yolo` (который, как и раньше, выполняет всё, кроме
  deny/ask).
- `suggested_rule` для «Всегда разрешать» строится по программе первого сегмента:
  `FOO=1 sudo pytest -q && ls` → `execute:pytest *`. `suggested_rules` (кортеж,
  `luna_core.policy.suggest_rules`) перечисляет по правилу `execute:<программа> *` на каждую
  простую команду, которую allow ещё не покрывает: для `cd src && ls` это
  `("execute:cd *", "execute:ls *")`. Если клиент возвращает в `Decision.approve(always=...)`
  ровно `suggested_rule`, агент сохраняет **все** `suggested_rules`, и та же составная команда
  дальше одобряется автоматически; любое другое (отредактированное) правило сохраняется как есть.
- «Всегда» никогда не сохраняет правило allow для `execute`, которое разрешило бы что угодно
  (`luna_core.policy.check_rule_safe`, исключение `UnsafeRule`): программа в правиле должна быть
  простым именем или путём (`^[A-Za-z0-9_./+-]+$` — без `*`, `?`, `[`, `$`, кавычек, `=`) и не
  входить в `RUNNER_PROGRAMS` — программы, запускающие другие команды: `sh`, `bash`, `zsh`,
  `dash`, `ksh`, `fish`, `csh`, `tcsh`, `eval`, `exec`, `source`, `.`, `env`, `command`,
  `builtin`, `sudo`, `doas`, `su`, `xargs`, `find`, `nohup`, `nice`, `timeout`, `time`,
  `stdbuf`, `watch`, `busybox`, `parallel`. Если хоть одна простая команда не даёт безопасного
  правила (или строку не удалось разобрать), `suggested_rules` пуст, и «всегда» сохраняет только
  `suggested_rule` — если оно само безопасно; иначе ничего не сохраняется, а ход получает
  `Notice` «rule not saved». Проверку делают и `Policy.remember_always`, и `append_rule`, так что
  `execute:* *` не записать никаким путём, в том числе строкой `always` от клиента. Правила,
  вписанные в конфиг руками, не проверяются. TUI под кнопкой «Разрешить всегда» показывает,
  какие правила будут сохранены.

Это консервативное приближение грамматики оболочки, а не полный парсер: команды, которые
запускают другие программы из аргументов (`xargs rm`, `find -exec rm`, `busybox rm`, `watch rm`),
по-прежнему видны только как `xargs …` / `find …`.
Для полной изоляции используйте `DockerSandbox`.

## Ответы на подтверждения

Когда вызов требует решения, ход отдаёт `NeedsApproval(request)` и ждёт:

```python
from luna_core import Decision, NeedsApproval

async for event in agent.run(session, text):
    if isinstance(event, NeedsApproval):
        r = event.request                          # call_id, name, args, description, suggested_rule(s)
        session.decide(r.call_id, Decision.approve())
        # Decision.approve(always="execute:pytest*")  также запоминает правило
        # Decision.edit({"command": "pytest -q"})      выполнить с изменёнными аргументами
        # Decision.reject("not in this repo")          модель увидит сообщение
```

Подойдёт и обычный словарь: `{"type": "approve"}`, `{"type": "edit", "args": {...}}`,
`{"type": "reject", "message": "..."}`, с необязательным `"always": "<rule>"`.
Передайте `persist_rule=fn` в `Policy`, чтобы сохранять правила «всегда» (например,
`luna_core.policy.append_rule(path, rule)` в `.luna/permissions.toml`).

Подводные камни: **неотвеченное подтверждение оставляет ход в ожидании**; `session.cancel_turn()`
(или закрытие генератора) отбрасывает всю пачку и ничего из неё не выполняет. В `run_sync` без
колбэка `approve` подтверждения отклоняются. Подтверждения субагентов идут через родительскую
сессию, поэтому отвечайте на них в той сессии, которую вы запустили.
Подтверждения по HTTP показаны в `examples/approvals_web.py`.

## Хуки

Хуки это колбэки в пяти точках: `session_start`, `pre_tool`, `post_tool`, `turn_end`,
`pre_compact`. Ключи payload (плюс `event`): у `session_start` это `session_id`, `workdir`;
у `pre_tool`: `session_id`, `tool`, `args`; `post_tool` добавляет `ok` и `output`; у `turn_end`:
`session_id`, `turn_id`, `text`; у `pre_compact`: `session_id`, `messages`. Хук `turn_end`,
вернувший `block=True` с `message`, ход не останавливает: ход продолжается, а `message`
добавляется как новое сообщение пользователя (пока позволяет `max_steps`). Блокирующий хук
`pre_compact` пропускает сжатие.

```python
from luna_core import Agent, HookResult, Hooks

hooks = Hooks()


async def no_force_push(payload: dict) -> HookResult | None:
    # payload: {"event": "pre_tool", "tool": "execute", "args": {...}, "session_id": ...}
    if "push --force" in payload["args"].get("command", ""):
        return HookResult(block=True, message="force-push is not allowed")


hooks.add("pre_tool", no_force_push, match="execute", timeout=5)
agent = Agent(provider, model, hooks=hooks)
```

Поля `HookResult`: `block` + `message` (сообщение возвращается модели), `args`
(заменяют аргументы инструмента), `context` (текст, добавляемый в диалог), `notices`.
Хуки выполняются в порядке регистрации; первый заблокировавший прерывает цепочку. Исключение
или тайм-аут превращается в уведомление и ход не блокирует.

### Командные хуки из конфигурации

```toml
[[hooks]]
event = "post_tool"
match = "write_file"      # необязательный glob по имени инструмента
command = "ruff format ."
timeout = 30
```

`luna_core.hooks.load_command_hooks(entries, cwd)` превращает такие записи в `Hooks`;
объединяйте через `hooks.extend(other)`. Команда получает JSON payload на stdin. Код выхода 0
продолжает ход (stdout может добавить контекст), код 2 блокирует (stderr уходит модели), любой
другой считается предупреждением. Тайм-аут убивает всю группу процессов.

## Отмена

`session.cancel_turn()` останавливает текущий запрос и работающие инструменты (группы процессов
убиваются), записывает `Cancelled` и исправляет повисшие вызовы инструментов, чтобы следующий
ход работал.
