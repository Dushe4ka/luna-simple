# Сессии

Сессия это диалог, хранящийся как журнал событий SQLite (режим WAL) с записью только в конец.
`EventLog(path)` это хранилище, общее для всех сессий процесса; `Session` это дескриптор
одного диалога.

```python
from luna_core import EventLog, Session

log = EventLog("/var/lib/myapp/sessions.db")           # файл и папки создаются по необходимости
session = Session.create(log, "/path/to/project", title="refactor")
same = Session.open(log, session.id)                 # позже или в другом процессе
for info in log.list(workdir="/path/to/project"):    # SessionInfo, сначала новые
    print(info.id, info.title)
```

## Чтение и восстановление

| Вызов | Результат |
|---|---|
| `session.messages()` | контекст модели, восстановленный из событий (сжатия применены, повисшие вызовы инструментов исправлены) |
| `session.entries()` / `session.records()` | записи транскрипта / сырые записи журнала |
| `session.usage()`, `session.cost()` | накопленные токены и стоимость |
| `session.todos()` | текущий план агента |
| `session.title` | первая строка первого сообщения пользователя, если заголовок не задан |

## Управление

| Вызов | Действие |
|---|---|
| `session.decide(call_id, decision)` | ответить на подтверждение (`Decision` или его словарь) |
| `session.pending_approvals` | id вызовов, ждущих решения (свойство) |
| `session.queue(text)` | доставить текст пользователя на ближайшей границе шага (рулевое управление) |
| `session.cancel_turn()` | попросить текущий ход остановиться; возвращает `False`, если простаивает |
| `session.busy` | `True`, пока идёт ход (свойство) |
| `session.undo()` / `session.redo()` | откатить или вернуть последний ход, диалог и файлы |
| `session.rewind(to_seq)` | отбросить диалог после порядкового номера |
| `session.fork(at_seq=None)` | новая сессия с историей до `at_seq` |
| `session.export("md" \| "html" \| "json")` | транскрипт в виде текста |
| `await agent.side_question(session, text)` | ответить по контексту без инструментов и без записи в журнал (`/btw`) |

Undo использует снимок дерева git на каждый ход в git-репозиториях и файловый журнал в остальных
случаях. `Session.create(..., undo=False)` отключает его.

Undo и redo затрагивают только то, что изменил ход. Пути, изменённые файловыми инструментами
(`write_file`, `edit_file`, `delete`), восстанавливаются; путь, который пользователь изменил после
хода, пропускается и называется в результате. Если в ходе выполнялся `execute` (или другой
изменяющий инструмент, не являющийся файловым), восстанавливается весь diff дерева за этот ход,
потому что команда могла изменить любой файл, и каждый путь вне файловых инструментов называется
(«also restored (changed by commands or outside Luna): …»). Известное ограничение: в таком ходе
файл, который пользователь правил во время хода, тоже восстанавливается, но называется. Ход,
конец которого не был записан (сбой), восстанавливает только пути файловых инструментов. SDK не
проверяет фоновые задачи: `Session.undo/redo/rewind` выполняются в любом случае. Команды
`/undo`, `/redo` и `/rewind` приложения Luna отказывают, пока работают фоновые задачи сессии; в
собственном коде сначала проверьте `background.list(session.id)` на задачи в статусе
`queued`/`running`.

## Сжатие контекста

```python
from luna_core import Compactor

agent = Agent(provider, model, compactor=Compactor(provider=provider, model="a-cheap-model"))
```

При заполнении 80% окна контекста самые старые сообщения пересказываются моделью, последние четыре
хода пользователя остаются дословно, а вся история остаётся в журнале. Отдаётся событие
`Compacted`. Значения по умолчанию: `Compactor(threshold=0.8, keep_turns=4)`.

## Подводные камни

- Одновременно в сессии идёт один ход: второй `agent.run` на занятой сессии бросает
  `LunaCoreError`.
- Подтверждение, на которое никто не отвечает, держит ход (и сессию) занятыми; отмените через
  `session.cancel_turn()`.
- `EventLog.list()` возвращает и дочерние сессии (субагенты, фоновые запуски, форки); при
  построении списка выбора сессий фильтруйте по `parent_id`.
- Закрывайте генераторы, которые перестали читать: `await events.aclose()`, чтобы ход был отменён,
  а инструменты остановлены.
- `log.delete(session_id)` одной транзакцией удаляет сессию, её события и (рекурсивно) дочерние
  запуски субагентов и фоновых задач. Форки (`meta={"kind": "fork"}`) — самостоятельные
  диалоги: они остаются, у них лишь обнуляется `parent_id` (`fork_seq` и `meta` сохраняются).
- `append` в удалённую (или несуществующую) сессию бросает `LunaCoreError` и ничего не пишет.
  `fork` и `set_meta` атомарны (одна транзакция `BEGIN IMMEDIATE`), в том числе между потоками
  и разными `EventLog` на одном файле.
- Потребители делят один `EventLog` на процесс; отдельные журналы в разных процессах открывайте
  только через один и тот же файл (блокировки обеспечивает SQLite).
