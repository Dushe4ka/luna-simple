# Changelog

Все заметные изменения Luna фиксируются здесь. Формат — по
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — по
[семантическому версионированию](https://semver.org/lang/ru/).

## [0.3.0] — 2026-09-11

### Добавлено

- Диагностика после правок: ключ `[agent] diagnose_command` (`"auto"` —
  Luna сама угадывает `ruff check` / `pyright` / `tsc --noEmit` / `go vet` /
  `cargo check` по маркерам проекта) запускает проверку после хода, тронувшего
  файлы, и кладёт находки в контекст следующего хода. `/diagnose` — запустить
  вручную.
- LSP-навигация: инструменты агента `goto_definition` / `find_references` /
  `hover` на базе `multilspy`, опционально через extra
  `luna-simple[lsp]`. Без extra инструменты недоступны, но работа
  продолжается как раньше.
- Автоформатирование: ключ `[agent] format_command` (`"auto"` по умолчанию)
  форматирует файлы, изменённые за ход, сразу после правок — перед
  диагностикой и verify.
- Пользовательские slash-команды из `.luna/commands/*.md` (пользовательские
  в `~/.config/luna/commands/`, проектные — в `<repo>/.luna/commands/`,
  проектные перекрывают одноимённые пользовательские): тело файла
  поддерживает `$ARGUMENTS` (подстановка аргумента), `` !`shell` `` (вывод
  команды оболочки) и `@file` (содержимое файла). `/commands` — список
  загруженных.
- `/undo` в git-репозиториях теперь откатывает **и** файлы, **и** разговор к
  началу хода (снапшот дерева через `git commit-tree` в начале каждого хода,
  без промежуточных коммитов в истории репозитория); появилась команда
  `/redo`, возвращающая отменённый ход. Вне git-репозитория поведение
  прежнее — файловый журнал `.luna/undo/<session>/` per-file, как в 0.2.0.
- Реестр моделей `luna/models.toml` (окно контекста + цена за миллион
  токенов input/output) и блок `[model.pricing]` в конфиге для
  переопределения/добавления моделей — `/usage` и тусклая строка-индикатор
  после хода теперь показывают ориентировочную стоимость `$` сессии.
- `/plan` — режим только для чтения: блокирует мутирующие инструменты
  (`write_file` / `edit_file` / `delete` / `execute`) без пересборки агента,
  подсказка в промпте REPL меняется на `luna (plan) ›`.
- `@имя_субагента текст` в REPL — прямая делегация сообщения указанному
  субагенту инструментом `task`, без промежуточной просьбы к модели.
- Структурированный вывод для CI/скриптов: `luna "…" --json` (или
  `--output-format json`) печатает один JSON-объект (`text`, `tools_used`,
  `usage`, `cost_usd`, `thread_id`) вместо потокового текста.

## [0.2.1] — 2026-09-08

### Исправлено

- Субагенты из `subagents.toml` теперь работают с реальным репозиторием
  под теми же deny-правилами, запросом одобрения и снапшотами `/undo`, что
  и основной агент: их `FilesystemMiddleware` получает тот же backend
  (`LocalShellBackend` с корнем в рабочем каталоге), а не эфемерную
  файловую систему в памяти. Декларативные субагенты наследуют
  `interrupt_on` основного агента, поэтому мутирующий вызов внутри субагента
  тоже поднимает запрос подтверждения. Мутирующие инструменты
  (`write_file` / `edit_file` / `delete` / `execute`) требуют `unsafe = true`
  в блоке `[subagent.<имя>]` — иначе жёсткая ошибка конфигурации при старте
  и `/reload`. Субагент без явного ключа `tools` теперь read-only (был —
  полный набор); встроенные `researcher` / `reviewer` read-only и не могут
  это отменить.
- Заблокированный или недоступный для записи `sessions.db` больше не роняет
  REPL: `SessionIndex` вырождается в no-op, чекпойнтер откатывается на
  in-memory saver с предупреждением `sessions.db unavailable … this session
  will not be saved` — сессия просто не сохраняется.
- `/compact` заменяет историю диалога сводкой на месте (LangGraph
  `RemoveMessage(REMOVE_ALL_MESSAGES)` + `update_state`) на том же треде —
  один вызов модели вместо двух полных ходов, без новой строки в
  `luna_sessions`.
- Журнал `/undo` привязан к треду сессии: `session_id` совпадает с
  каноническим `thread_id`, поэтому `luna --continue` возобновляет тот же
  журнал — `/diff` и `/undo` видят изменения прошлого запуска. `/compact`
  сохраняет журнал, `/new` делит его в рамках одного процесса. Старые
  журналы чистятся при старте (`undo.gc()`: старше 7 дней / больше 20
  каталогов).
- `/undo` больше не удаляет изменённый **бинарный** файл: pre-image для него
  не снимается, поэтому откат отказывается и сообщает об этом. Записи в
  журнал получили флаг `existed`. Пути только на чтение (`/diff`, предпросмотр
  `/undo`) больше не создают каталог журнала.
- deny/allow-правила принимают `*` (любой инструмент) и сегменты-группы:
  `write` = {write_file, edit_file, delete}, `fs` = write + read-only
  fs-инструменты. `deny = ["*:.env"]` блокирует `.env` для всех
  инструментов, `write:secrets/*` — для всех мутаторов. Голое
  `write_file:.env` по-прежнему матчит только этот один инструмент.

## [0.2.0] — 2026-09-08

### Добавлено

- Долговременные сессии: каждая сессия REPL и одиночный запрос
  чекпойнтятся в `~/.config/luna/sessions.db`. `luna -c` / `luna --continue`
  возобновляет последнюю сессию для текущего каталога, `luna --resume [ID]`
  выбирает конкретную (без ID — интерактивный список). В REPL — команды
  `/sessions` (список сессий каталога) и `/resume <n>` (переключиться на
  выбранную).
- Учёт токенов: тусклая строка `ctx ~X/Y · turn … · session …` после каждого
  хода; `/usage` — подробная разбивка по ходам.
- `/compact` — сжимает диалог в плотную заметку-хендофф и продолжает работу
  на свежем, компактном треде.
- Упоминания `@file`: `@путь` (или `@"a b.py"`) в сообщении подставляет
  содержимое файла; `/add путь …` закрепляет файлы в каждом следующем ходе,
  `/drop` открепляет, `/context` показывает закреплённое.
- Правила доступа: блок `[permissions]` в `config.toml` и/или
  `<repo>/.luna/permissions.toml` со списками `allow` / `deny` вида
  `"<инструмент>:<glob>"` (например `deny = ["execute:git push*",
  "write_file:.env"]`). `deny` перекрывает даже `--yolo`; в запрос
  подтверждения добавлен пункт `[a] always`, который дописывает правило
  `allow` в `.luna/permissions.toml`.
- Уровни памяти `.luna/memory/`: `project.md` / `conventions.md` /
  `decisions.md` / `failures.md` подгружаются в системный промпт рядом с
  `AGENTS.md`; инструмент агента `remember` дописывает в них датированные
  заметки (с подтверждением; `/reload` — чтобы подхватить).
- Проверка после правок: ключ `[agent] verify_command` (например
  `"uv run pytest -q"`) — после хода, изменившего файлы, Luna запускает
  команду, а при провале один раз отдаёт вывод агенту на исправление и
  перепроверяет. `/verify` запускает проверку вручную.
- `/diff` и `/undo`: Luna снапшотит каждый `write_file` / `edit_file` /
  `delete` в `.luna/undo/<session>/`; `/diff` показывает суммарный diff
  сессии, `/undo` откатывает последнее изменение. На старте — предупреждение,
  если рабочее дерево git грязное.
- `luna init` / `/init` — исследует репозиторий и создаёт либо обновляет
  `AGENTS.md`.
- `/model <name>` / `/provider <key>` — горячая смена модели или провайдера
  прямо в сессии с сохранением треда; `/provider` без ключа печатает подсказку
  `luna config set-key`.
- `[model] fast` — необязательная более дешёвая модель (полная строка
  `<префикс>:<модель>`, например `anthropic:claude-haiku-4-5`), которую
  используют встроенные субагенты `researcher` / `reviewer`.

### Известные ограничения

Принятые на этот релиз ограничения (`/compact` без учёта токенов и verify,
свежий журнал `/undo` после `--continue`, deny по точному имени инструмента,
субагенты вне снапшотов и правил) описаны в разделе «Ограничения» README.

## [0.1.0] — 2026-09-06

### Добавлено

- Лёгкий CLI-агент для кода на `deepagents` (команды `luna` / `luna-simple`).
- Потоковый REPL на `rich` и режим одного запроса (`luna "…"`).
- ANSI-заставка «ночное небо» — светящаяся луна с орбитой, звёздное поле,
  созвездия, комета, облака, линия горизонта и отражение в море, надпись
  `L U N A` и слоганы по углам; компактный баннер для узких терминалов
  (`--no-splash` чтобы пропустить).
- Пять провайдеров моделей через `init_chat_model` из LangChain: `anthropic`
  (по умолчанию), `deepseek`, `openai`, `google`, `ollama`.
- Слоистая конфигурация: флаги CLI > окружение > `./.luna.toml` >
  `~/.config/luna/config.toml` > значения по умолчанию.
- Подтверждение действий человеком (human-in-the-loop) для `write_file`,
  `edit_file`, `delete` и `execute`; `--yolo` отключает все запросы.
- Бэкенд реальной файловой системы с корнем в рабочей директории.
- Мастер `luna setup` и подкоманды `luna config` (`path`, `show`, `set`,
  `set-key`, `unset-key`). API-ключи хранятся в
  `~/.config/luna/credentials.toml` (права `0600`); переменные окружения
  приоритетнее. Первый запуск без ключа предлагает запустить мастер.
  `--no-input` отключает любые интерактивные запросы.
- Расширения: подкоманды `luna mcp` / `luna skills` / `luna agents` и
  инструменты агента `manage_mcp` / `manage_skills` (с подтверждением).
  MCP-серверы в `mcp.json` формата Claude; скилы в стиле Anthropic; встроенные
  субагенты `researcher` и `reviewer` плюс пользовательские в `subagents.toml`.
  Курируемый реестр (`luna/registry.py`, расширяется через `registry.toml`)
  разрешает имена. `langchain-mcp-adapters` — это extra `luna-simple[mcp]`.
- REPL: `/reload` пересобирает агента в сессии с текущим конфигом; реплики
  оформлены линией `● luna`, так что текст пользователя и агента больше не
  сливается.
